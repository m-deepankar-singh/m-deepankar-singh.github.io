Case study № 1 · AWS Neuron NxDI

Bringing a hybrid DeltaNet model to AWS Trainium — with no reference implementation

lead author · upstream contribution · PR #173 · ~57K LOC across 95 files · validated on trn2.3xlarge

Qwen 3.6-27B is a hybrid: DeltaNet linear-attention layers interleaved with GQA attention. No serving path existed for it on AWS Trainium — not in the framework, not anywhere. This is the account of building one from zero: custom kernels, a stability failure that passed every unit test and still produced garbage on hardware, and the caching work that cut warm start latency by up to 18×.

1The problem

Hybrid architectures break the assumptions serving frameworks are built on. A standard transformer needs one thing cached between tokens: the KV cache. A DeltaNet + GQA hybrid needs two — paged KV for the attention layers, and a recurrent state (a 128×128 matrix per head) for the linear-attention layers. AWS Neuron's distributed inference framework (NxDI) had no support for the architecture, and no third-party reference existed to port. The baseline had to be designed, not adapted.

The first working version shipped in two weeks. It then matured into PR #173 — roughly 57K lines across 95 files, contributed upstream as lead author.

2Three kernels for DeltaNet

DeltaNet's recurrence doesn't map onto anything in Neuron's kernel library, so I wrote three custom NKI kernels — basic, chunked, and fused. The fused variant is the interesting one: it keeps the 128×128 recurrent state resident in SBUF (on-chip memory) across all chunks, processing an entire sequence in one kernel call per (batch, head) rather than round-tripping state through HBM between chunks.

3The bug that only existed on hardware

The fused kernel's solve step passed every unit test — and produced incoherent tokens on the device. Under realistic gate scales the fused solve diverged numerically; nothing in isolated testing had exercised those value ranges end-to-end. I traced it with chained coherence validation — checking intermediate states layer by layer against a reference path until the divergence localized — and replaced the failing step with a direct triangular solve.

The fix cost about 18% of decode throughput. That trade was correct: a fast kernel that emits garbage has a throughput of zero. It's the kind of decision unit tests can't make for you — only hardware validation surfaces it, and only a coherence harness localizes it.

4Making cold and warm starts fast

With correctness settled, latency was next. Native chunked prefill brought cold time-to-first-token at 16K context from ~27s down to 6.8s — a 3.8× improvement — while prefill throughput rose from 623 to 2,395 tok/s.

Warm starts went further. I brought native vLLM automatic prefix caching to the hybrid — which meant caching not just KV blocks but the recurrent and convolutional state alongside them, with strict prefix-cache exactness, and patching scheduler-aware continuation handling into vLLM v1's internals.

up to 18× faster warm TTFT hybrid prefix cache: KV + recurrent state, strict exactness

Memory was the last constraint. Selective FP8 on the MLP path — keeping the numerically sensitive recurrent state in BF16/FP32 — freed enough headroom for 256K-token context on a single trn2.3xlarge.

5Framework work, not a plug-in

Supporting a hybrid properly meant modifying NxDI's core: async execution, the attention base, the model wrapper. I also added a segmented-CTE attention kernel and shipped a multimodal path — vision encoder + text decoder with interleaved mRoPE. The serving surface is a vLLM Neuron registry with OpenAI-compatible endpoints, SSE streaming, and thinking-token injection.

6Validation

Everything above is hardware-validated on trn2.3xlarge (TP=4, LNC=2, SDK 2.29): a 256K-token coherent generation baseline, 97.5% HF-greedy token match against the reference implementation, 12.7K lines of tests, and committed benchmark evidence covering decode throughput, prefix-cache exactness, and context sweeps. A follow-up ported MTP speculative decoding to the same stack — ~2× decode throughput, token-ID match against the non-speculative baseline.
