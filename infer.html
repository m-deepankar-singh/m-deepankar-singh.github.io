Case study № 2 · Serverless inference

INFER: a serverless platform where sleeping models wake in one second

solo builder · 2026 · multi-tenant L40S GPUs · EC2 Spot fleets

Commercial serverless GPU endpoints pay for cold starts in minutes. INFER is a Modal/RunPod-style platform built around a different bet: many models sharing one GPU, sleeping in pinned host RAM at ~3% of GPU cost, and waking in ~1 second. This is how the ladder works — and how it survives losing its hardware.

1The tiered-warmth ladder

The core mechanism is vLLM sleep mode, which uses CUDA virtual-memory-management to offload model weights out of VRAM without tearing down the process. INFER turns that primitive into a two-tier ladder: T0, awake in VRAM and serving; and T1, weights parked in pinned host RAM. Demotion to T1 releases the GPU for other tenants; promotion back is a memory copy, not a model load.

2The slot manager

Sharing GPUs safely is a scheduling problem. The slot manager (FastAPI) owns it: per-GPU VRAM budgeting with auto-sizing, RAM admission control so T1 never overcommits host memory, idle demotion, and per-second tiered billing meters.

The hardest scheduling case was the thundering herd: 24 simultaneous requests to sleeping models produced a 210-second contention storm as wakes fought over VRAM. Cohort wake scheduling — batching wakes into cohorts instead of racing them — cut the same storm to 12.7 seconds.

3Keeping the KV cache across sleep

Waking fast is wasted if the model wakes amnesiac. With LMCache, KV state persists across sleep: at 4.8K context, restoring a prefix takes 130ms against 500ms to recompute it. The gateway above all of this is OpenAI-compatible — a drop-in base_url swap — with SSE streaming, a dynamic worker registry, request observability, and a durable append-only usage ledger.

4Surviving the loss of the hardware

The fleet runs on EC2 Spot for cost, which means the platform must assume its GPUs can vanish with two minutes' notice. A custom controller launches diversified instant Spot Fleets from a slim self-provisioning AMI — boot to serving in ~3 minutes — and scales to zero when idle. Interruptions are handled by a tested state machine: an IMDS watcher catches the reclaim notice, tenants evacuate in ~2 seconds, traffic falls back to On-Demand capacity, and the controller automatically reclaims Spot when it returns.
